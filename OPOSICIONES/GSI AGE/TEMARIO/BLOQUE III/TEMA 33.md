# Tema 33: Pruebas

Pruebas. Planificación y documentación. Utilización de datos de prueba. Pruebas de software, hardware, procedimientos y datos.

## Pruebas

### Planificación, pruebas y datos

El plan de pruebas define alcance, estrategia, niveles, tipos, responsabilidades, entorno, calendario, criterios de entrada/salida, riesgos y evidencias. Cada caso contiene objetivo, precondiciones, datos, pasos y resultado esperado; los defectos se registran con severidad, prioridad, versión y estado. La trazabilidad vincula requisitos, riesgos y pruebas. Automatizar pruebas repetitivas aporta rapidez, pero exige mantenimiento y no sustituye pruebas exploratorias.

Los datos deben representar casos normales, límites, errores, volúmenes y combinaciones; se protegen datos personales mediante minimización, anonimización o datos sintéticos. Se evita usar copias reales no autorizadas en pruebas.

### Tipos de pruebas

Pruebas unitarias verifican componentes; integración, interfaces; sistema, el producto integrado; aceptación, su adecuación a necesidades. Regresión comprueba que cambios no rompan funciones. Pruebas funcionales contrastan comportamiento; no funcionales miden rendimiento, carga, estrés, disponibilidad, seguridad, accesibilidad y usabilidad. Caja negra se basa en entradas y salidas; caja blanca examina estructura y cobertura. Revisiones estáticas detectan defectos sin ejecutar.

También se verifican hardware, instalación, procedimientos de operación, backup y recuperación, interfaces, migración y calidad de datos. La salida requiere criterios acordados, defectos críticos resueltos o aceptados formalmente, y evidencias reproducibles. Un resultado de prueba válido depende de entorno conocido y configuración controlada.
